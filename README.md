# Gowri Toys — Attendance Management System

A mobile-first attendance management app for a toy manufacturing company (~200 workers,
two shifts). Built with **React Native (Expo) + TypeScript + Expo Router** on the client and
**Supabase** (PostgreSQL, Auth, RLS, Storage, Edge Functions) as the complete backend.

## Features

- **Two roles** — Admin (full control) and Supervisor (marks attendance)
- **Worker management** — create workers, auto-generated unique Worker IDs (`WRK001`, `WRK002`, …)
- **QR codes** — each worker gets a QR containing only `{ "type": "worker", "workerId": "WRK001" }`
- **QR scanning** — supervisors select Shift 1 or Shift 2 and scan worker badges to mark attendance
- **Duplicate prevention** — unique DB constraint (`worker_id + shift_id + attendance_date`) rejects double marking
- **Dashboards** — today's attendance per shift, active worker count, recent records
- **Attendance views** — daily records with filters (date, shift, department, search), per-worker monthly history, monthly roll-up
- **Monthly PDF reports** — generated by an edge function, stored in Supabase Storage, downloadable via signed URLs
- **Row Level Security** — role-based access enforced in PostgreSQL

## Setup

### 1. Supabase backend

1. Create a project at [supabase.com](https://supabase.com).
2. Open **SQL Editor** and run the contents of `supabase/migrations/00001_init.sql`.
   This creates: `profiles`, `workers`, `shifts`, `attendance`, `reports`,
   `company_settings`, all indexes, triggers, seed shifts (`SHIFT_1`, `SHIFT_2`),
   the RLS policies and the `attendance-reports` storage bucket.
3. Deploy the edge functions:

   ```bash
   supabase login
   supabase link --project-ref <your-project-ref>
   supabase functions deploy mark-attendance
   supabase functions deploy generate-monthly-report
   ```

   (Or paste each function inside `supabase/functions/*/index.ts` in the
   **Edge Functions** section of the dashboard.)

4. Create users (Authentication → Users → **Add user**). In **User Metadata**
   add:

   ```json
   { "full_name": "Admin Name", "role": "admin" }
   ```

   or `"role": "supervisor"`. A matching `profiles` row is created automatically
   by the `handle_new_user` trigger.

5. Optionally set company details in the **Table Editor** → `company_settings`
   (used in the PDF header).

### 2. Mobile app

1. Install dependencies:

   ```bash
   npm install
   ```

2. Create the environment file:

   ```bash
   copy .env.example .env
   ```

   Then edit `.env` with your project values from **Settings → API**:

   ```
   EXPO_PUBLIC_SUPABASE_URL=https://<ref>.supabase.co
   EXPO_PUBLIC_SUPABASE_ANON_KEY=<anon key>
   ```

   > The app only ever uses the public/anon key. The service-role key is used
   > exclusively inside edge functions on the server.

3. Run the app:

   ```bash
   npm start
   ```

   Scan the QR with Expo Go (Android) or run in an emulator.

## Workflow

1. **Admin** → Workers → add workers (the system generates `WRKxxx` IDs).
2. **Admin** → Worker detail → **QR Code** → share/print the badge.
3. **Supervisor** → Scan tab → select **Shift 1** or **Shift 2** → **Open Scanner**.
4. Scan a worker's QR → confirm → **Mark Attendance** → success, scanner auto-resets.
5. **Home / Attendance / Monthly** tabs show record counts and details.
6. **Reports** tab → pick a month → **Generate PDF Report** → download from history.

## Security notes

- Attendance inserts happen **only** through the `mark-attendance` edge function,
  which uses the service-role key and derives `marked_by`, `marked_at`, and
  `attendance_date` server-side. The client cannot fake records.
- The unique constraint `(worker_id, shift_id, attendance_date)` de-duplicates at
  the database level, not just in the UI.
- Report downloads use **signed URLs** — the `attendance-reports` bucket is private.
- Shift timings are not enforced (by design); the supervisor picks the shift when scanning.

## Customization

- **Timezone** — attendance "today" is computed server-side. Set the
  `APP_TIMEZONE` secret on your edge functions (default `Asia/Kolkata`).
- **Reports bucket** — override with the `REPORTS_BUCKET` secret (default
  `attendance-reports`).
